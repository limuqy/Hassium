## 1. 方法与口径

- 执行：单会话脚本逐场串行（未用批量脚本），`.\scripts\runtime-smoke-test.ps1 -Ver <ver> -Loader <loader> -Phase I -SessionId <id> [-Scenario <name>]`。
- 参数：`DelayMs=20000`（R1 服 VD=20 → 断连 → R2 服 VD=10）、`ReconnectDelayMs=1500`、客户端 `renderDistance=20`（classic 另钉 `chunk.maxRenderDistance=16`）、超时 180s/300s（脚本默认）。
- 存档：`parity_<loader>_<ver>` 跨场复用（classic）；`seedgen` / `dimension` 场景脚本内**强制 `-CleanWorld`**。
- 客户端缓存：每场启动前脚本删除 `hassium_cache`（R1 恒冷启动）。
- 判定：`result_<id>.json` + Python analyzer（`scripts/smoke/analyzer.py`）+ PROBE JSON（`stats/<id>_roundN_probe.json`）+ 客户端 `CLIENT_STATS` 六行。
- 客户端统计口径（`MetricsSemantics`）：**光照重算 = 区块加载 + 部分命中**（2026-09-20 用户拍板），与「区块加载」行同值；光环柱的引擎工作不计入。

## 4. 读数解读与偏差归因

1. **1.21.4 起 R1 读数上台阶（1705→1749 / 1529→1573、R2 OVD 636→616）**：原版 1.21.4 把
   `ChunkTrackingView.isWithinDistance` 改成纯欧氏圆，VD20 权威形状 1529→1573 柱；光环修复后计算域
   = 新形状膨胀 1749。**是新形状下的正确值，不是回归**（≤1.21.3 逐项保持基线值）。
2. **冷世界首跑 vs 暖世界**：`1.21.1_neoforge_I_m1`（`parity_neoforge_1_21_1` 当场新建）R2 部分命中
   279、光照 79.5%；暖世界复跑（m2）回到 13 / 98.8%，与 fabric/forge 同量级。冷世界场的 R2 数据
   不具基线可比性。
3. **部分命中数 = 石墙注入触发的分段增量**：1.21.1+ 为方块级 DELTA（14~65 波动），1.20.1 为 4~7；
   forge 1.20.1 另有 3 根整柱回退（rx=3），缓存 99.5%，门禁 PASS。
4. **meshCompiled 为异步网格编译在探针时刻的计数**（R1 425~681），天然抖动，不作门禁信号。
5. **seedgen 场景读数特征**（单轮，`chunk.seedGenEnabled=true` 双端）：`rx=0`（无网络整柱）、
   本地生成 1835/1815 柱、本地命中 100%、缓存 95.5%（全命中+部分命中）、光照命中 14.9%（本地物化
   全量算光）、带宽压缩 ~61%、流量节省 ~89%。两端一致。
6. **dimension 场景读数特征**（四轮切维，`-CleanWorld`）：每轮 `rx=1705` / 交付 1529；R2（下界）
   累计「区块加载 3410」= 主世界 1705 + 下界 1705；缓存 0%（冷）、光照重算 3410（全量）、
   OVD 0（切维轮不适用）；下界 region 落盘 4（probe `disk.dimensions.nether`）。

## 5. 事件 A：`1.21.4_fabric_I_m1` FAIL（已修复）

- 现象：Round1/2 统计 pass、退出码 0、无空间空洞，但 analyzer 报 `TRACE_EXPECTED_NOT_PRESENT` +
  `TRACE_INJECTED_NOT_READY`（P0，各 132）；R1 交付 1573 ≠ 基线 1529。
- 根因（已验证）：① analyzer `_player_chunk` 用截断（`int()>>4`）算玩家区块，本场玩家 z=-0.5 →
  锚点偏 1 格（同一份 trace 按 floor 锚点 0 缺口在形状内、按截断锚点 21 个）；② analyzer
  `_in_authority_shape` 写死 1.21.4 前的形状公式；③ **产品侧** `ChunkShapeCompat.containsDilated`
  同样写死旧公式、未委托原版 → 1.21.4+ 计算域（1705）滞后于交付域（1749），**新权威形状 44 柱
  3×3 缺邻**（红线「缺邻 → Bedrock 挡天光」触发条件）。
- 修复：`containsDilated` 改为「坐标向中心收缩 dilate 后委托 `contains`」（零新增 `#if`，
  两代公式下与朴素切比雪夫膨胀逐点等价，≤1.21.3 与旧实现逐点相同）；analyzer 锚点改 floor +
  形状公式按版本分段；新增 `HaloAnchorTest` 5 例。
- 验证：`1.21.4_fabric_I_m2` PASS（R1 1749/1573/1573，= 预测值，0 空洞）；`1.20.1_fabric_I_m2`

  三锚点编译 + `scanVersionBoundaries` 绿；analyzer 单测 31 个全绿。用户已在 1.21.4 游戏内

## 6. 事件 B：`1.21.1_fabric_I_dimension` FAIL（profile 残留，harness）

- 现象：下界轮 `clientCache.loadedChunks=0`、trace 全 0，`assertProbe NETHER_CHUNKS` 失败 →
  客户端 fail-fast 退出（exit 1）。
- 根因（已验证）：上一场 `seedgen` 的 profile 把 `chunk.seedGenEnabled = true` 写进 loader 的
  client/server toml；**`dimension` 没有 profile 文件**，脚本也不清理 `config/hassium/*.toml`
  → dimension 场继承该开关。实测首跑时 fabric 两侧 toml 均为 true；把该键复位为 false 后同一命令
  复跑（`_dimension2`）即 PASS（下界完整交付 1529 柱 / rx 1705）。对照：首跑 R1
  `locallyGenerated=1800, rx=0`（走 seedgen 路径），复位后 R1 `locallyGenerated=0, rx=1705`。
- **产品侧待跟进【推断】**：`chunk.seedGenEnabled=true` 时会话中切维（主世界→下界）下界 40 秒
  零交付 —— 客户端虚拟玩家已 reseat 到 the_nether、tracking session 已启动，但随后零本地物化 /
  零 acquire / 零 pull（主世界侧物化在切换后 1 秒也静默）；同时刻在途的主世界 compare 请求被服务端
  以 `Rejection.DIMENSION` 拒绝（`ShadowPullServer` 取 `player.level()` 维度，与请求维度不符）。
  推断根因 = seedgen 本地物化路径仍锚在登录时维度、reseat 后未重新武装（**未定位到代码级证据**）。
  seedgen 设计为单轮场景、不与该切维组合，故列为待跟进项。
- 建议修法（一行）：新增 `scripts/smoke/profiles/dimension.profile.properties`，内容
  `chunk.seedGenEnabled = false`（与 classic 的复位同理），从源头消除残留。
