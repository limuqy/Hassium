## 2. 1.21.4 fabric FAIL 事件与修复

### 现象

`1.21.4_fabric_I_m1`：Round1/2 统计 pass、客户端退出 0、无空间空洞，但 analyzer 报
`TRACE_EXPECTED_NOT_PRESENT` + `TRACE_INJECTED_NOT_READY`（P0，各 132）。R1 交付 1573 ≠ 基线 1529。

### 根因【已验证】

1. **原版 1.21.4 改了视距形状公式**（反编译源码核对 1.21.3/1.21.4/1.21.5/1.21.11）：
   旧 `ChunkTrackingView.isWithinDistance`（chebyshev 角区折算，VD20 = 1529 柱）→ 新纯欧氏圆
   `max(0,|d|-2)²` 求和（VD20 = **1573** 柱）。Hassium `ChunkShapeCompat.contains` 委托原版，
   交付域正确跟进；实测交付集与新公式 symdiff 0。
2. **analyzer `_player_chunk` 用 `int(coord) >> 4`（截断）**：本场玩家 z=-0.5，锚点偏 1 格。
   同一份 trace 按正确 floor 锚点：132 缺口 **0 个**在权威形状内（全是设计上不交付的光环）；
   按截断锚点：21 个被算进形状内 → 假 P0。（内存中「已修」记录与树不符：修复从未提交，
   本次重新落地并补 `HaloAnchorTest`。）
3. **analyzer `_in_authority_shape` 把旧公式写死**：旧形状是新形状真子集（差 44 柱）。
   本场 P0 直接原因是 ②；但写死旧公式会把「新形状外环漏交」误判成光环（假 PASS 门洞），一并修复。

### 产品侧新发现（同批修复）

`ChunkShapeCompat.containsDilated`（光照光环/计算域）同样写死旧公式、未委托原版 → 1.21.4+ 上
计算域 = 旧形状膨胀（1705）≠ 新形状膨胀（1749），**新权威形状 44 柱 3×3 缺邻**（正是红线
「缺邻 → 引擎按 Bedrock 挡天光」的触发条件）。修复后用户 2026-09-20 已在 1.21.4 游戏内
**目视验收屋檐光正常**。

### 修复与验证

- `common/.../compat/ChunkShapeCompat.java`：`containsDilated` 改为「坐标向中心收缩 dilate 后
  委托 `contains`」——零新增 `#if`（1.21.4 非编译锚点、白名单无对应 token，写 `< MC_1_21_5`
  会把 1.21.4 错分进旧段），单调性保证其恰为切比雪夫膨胀，并自动跟随原版后续变化。
  数值验证：vd∈{10,16,20}×dilate∈{0,1,2} 与朴素膨胀定义逐点等价；≤1.21.3 与旧实现逐点相同。
- `scripts/smoke/analyzer.py`：`_chunk_of`（floor 取整）+ `_in_authority_shape` 按版本分段
  （1.21.4 判别点 `(21,8)`：旧公式外/新公式内），`Ver` 透传至 halo 判定。
- 验证：`ChunkShapeDilationTest` 1.20.1 与 1.21.5 两段 5/5 绿；`common:compileJava`
  1.20.1/1.21.5/1.21.11 绿；`scanVersionBoundaries` 绿；analyzer 单测 31 个全绿（新增 5 个）。
- 冒烟复跑：`1.21.4_fabric_I_m2` **PASS**（R1 1749/1573/1573，= 预测值；0 空洞）；
  `1.20.1_fabric_I_m2` PASS 且与基线逐项相同（旧段零漂移哨兵）。
