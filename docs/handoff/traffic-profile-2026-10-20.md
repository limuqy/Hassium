# 2.X 流量画像：普通活动、静止观察与工厂挂机

状态：首轮流量画像完成。两个重点组合的可复现场景及 1.21.1 用户真实工厂均已实测。当前仅增加开发环境采样、自动场景与分析脚本，**未实现 AFK 识别或节流，没有改变产品的发包策略**。

## 口径与场景

服务端 `EgressPipeline.METRICS.wireBytes` 记录 PLAY 期成功写出的 TCP 载荷，包含 Minecraft 长度与压缩前缀；不包含 TCP/IP 头、ACK、重传和登录流量。这里是单客户端、本机 TCP 直连的实际成功写出量，不是把原始包大小相加，也不是公网网卡上传统计。`KiB/s = B/s ÷ 1024`。

`native_v3` 用于识别压缩前包类型，`agg_v3` 用于检查实际聚合帧；二者不能相加，也不能把原始包占比直接当作删除该类包后的带宽收益。异步编码、成功写出与主线程快照之间存在边界偏差，分析脚本检查采集与计数器差异。

共同条件：2.0.0 分支（基于 `d1e6313b`，本次增加开发采样代码），Forge 47.4.21 / NeoForge 21.1.236，单客户端；服务端/客户端视距及服务端模拟距离 10，正常 20 TPS；原版压缩阈值 256 B，聚合开启，ZSTD level 3，50 ms 上限、262144 B 批次；原有实体距离、密度、预算与错峰策略开启。SeedGen、OVD 关闭，区块缓存、分段增量与光照剥离开启。正式场次使用空的独立客户端缓存，结束后恢复原缓存、配置、字典与 options。统一训练字典 SHA256：

`E393FA8D66693E71A5440DD01EA0C438B097B3041B70D596654304A981A7C9CA`

这份字典保存于前置 1.20.1 场次，正式采样统一复用，不在采样中切换。它不是针对两个版本分别调优的最佳字典，因此跨版本差值也可能受字典与协议内容匹配程度影响。

| 样本 | 普通活动 | 静止观察 | 工厂挂机 |
|---|---|---|---|
| 1.20.1 Forge、1.21.1 NeoForge 可复现场景 | 普通步行与四向转向，相同路线三段 60 秒；第一段包含路线首次加载 | 位置/视角固定，无手部操作，三段 60 秒 | 16 组原版侦测器时钟、活塞、投掷器、漏斗和箱子；三段 60 秒，再测试长按/间隔攻击各 60 秒 |
| 1.21.1 用户真实工厂 | 本轮不在此存档测活动路线 | 与 AFK 具有相同位置/视角时，不能靠流量区分人的意图 | 每轮从同一 ZIP 恢复，冻结预热，解冻后 20 TPS 测 60 秒，再冻结；独立重启重复 |

可复现场景是负载样本，不代表普通玩家群体的平均值。普通活动为小范围四向步行，未覆盖持续远距离飞行。首次路线加载与后续缓存命中应分开看；三个连续窗口不是三次独立启动。两版采用同一生成配方和种子 42，动物 AI、原有地形实体、版本协议与加载器均可能带来差异，并非逐 tick 相同的确定性回放。静止观察与工厂测点的环境、实体距离不同，不能把二者之差解释成 AFK 的因果效应。

控制场景在平台/动物准备后预热 60 秒，静止观察前等待 15 秒，工厂启动后预热 45 秒；这些阶段及进服初始区块加载不计入均值。真实工厂冻结预热 45 秒、解冻等待 2 秒后开始采样，因此其窗口代表机器恢复运行后的早期负载。

工厂控制场景通过箱子产出和投掷器余料检查持续运行；手部测试使用开发场景调用原版交互接口，对生存模式下不可破坏的基岩持续/间隔攻击，不直接构造网络包。真实工厂保留原有机器与规则，以末尾五秒持续的方块状态/事件流检查运行状态，不宣称每台机器均已验收。

长按和间隔攻击分别只有一个 60 秒窗口，且按顺序运行，掉落物数量与实体 ID 编码长度会随时间变化；这些窗口用于覆盖“位置/视角不变但有持续输入”的情况，不用于精确估计输入本身增加或减少了多少上传量。

## AFK 的定义与后续切入点

用户定义：人物位置与视角长期稳定，无操作、挂机长按或持续间隔攻击均可属于 AFK。持续有攻击包不自动代表真人正在主动活动。静止观察和无操作挂机可能产生相同的客户端信号，需要后续讨论显式模式、观察意图或更保守的识别方案。

优先调查减少非交互实体的位置、速度、朝向与其他可重建状态同步。现有 `EntityUpdatePacing` 仍沿用每实体共享的 `ServerEntity.positionCodec` 基线，并根据最近观察者决定共享节拍，不是每个观察者独立的实体复制。源码锚点：`server/entity/EntityUpdatePacing.java` 的 `nearestObserver`、`effectiveInterval`，以及 `mixin/server/MixinServerEntity.java` 的 `sendChanges` 字段重定向。

建议第一阶段先研究**所有实际观察者都处于 AFK 的实体**：可沿原生共享基线降低复制频率；存在活动观察者就保持正常策略。混合观察者下的独立降频另作下一阶段，必须解决每连接基线、生命周期和恢复。不能直接在出口删除相对位移包，也不能因某个 AFK 玩家而降低共同观察该实体的活动玩家质量。

工厂的方块变化、容器状态、交互确认、健康和连接控制需要独立处理，不按“玩家没动”整体延迟。

本轮不估算尚未实现的 AFK 节省百分比。真实收益还取决于允许的状态陈旧时间、唤醒恢复成本，以及压缩历史在降低更新频率后的变化。

后续已形成[AFK 实体同步深入方案](research-2026-10-20-afk-entity-sync.md)：参考本地 BandwidthOptimizer，定义识别、长按/间隔攻击豁免、混合观察者、运动快照、基线恢复与实验门禁；仍处于设计阶段。

## 复现与证据

PowerShell 7 与 Python 3.11+（分析脚本仅用标准库），先生成控制场景，再选择组合运行。两个版本串行执行，避免同一工作区并行切换构建版本：

```powershell
python scripts/smoke/build-traffic-profile.py
.\scripts\traffic-profile.ps1 -Ver 1.20.1 -Loader forge -SessionId <new-id> -Dictionary <fixed-dictionary.bin>
.\scripts\traffic-profile.ps1 -Ver 1.21.1 -Loader neoforge -SessionId <new-id> -Dictionary <fixed-dictionary.bin>
.\scripts\traffic-profile.ps1 -Ver 1.21.1 -Loader neoforge -SessionId <new-id> -Dictionary <fixed-dictionary.bin> -WorldZip '<original-1.21.1-zip>'
python scripts/smoke/analyze-traffic-profile.py build/traffic-profile/<new-id>
python -m unittest scripts.smoke.test_traffic_profile -q
```

每场目录包含双端日志、实际生效配置、输入字典、原始包导出、冒烟结果，以及 `traffic-summary.json`、`traffic-windows.csv`、`traffic-packets.csv`。原始大文件、存档和缓存留在忽略的 `build/traffic-profile/`，不提交用户存档。

可随代码保存的小型汇总：

- [场景汇总 CSV](traffic-profile-2026-10-20-summary.csv)：时长、字节、均值、窗口范围、TPS 与协议错误。
- [25 个窗口 CSV](traffic-profile-2026-10-20-windows.csv)：成功写出量、约 1 秒 P95/峰值、位置/视角范围、产出、余料与采集差异。
- [原生包类别 CSV](traffic-profile-2026-10-20-categories.csv)：各窗口的压缩前包数、字节与占比。

合并入口为 `python scripts/smoke/merge-traffic-profiles.py --output-prefix docs/handoff/traffic-profile-2026-10-20 <五个有效场次目录>`；它拒绝冒烟失败或画像校验失败的输入。

已执行验证：

- `forge:compileJava -Pmc_ver=1.20.1`、`neoforge:compileJava -Pmc_ver=1.21.1` 通过；版本边界扫描通过。
- 冒烟分析器及画像分析单元测试共 45 项通过，其中画像专用三项分别检查字节口径、静止/冻结误测、缺失结束边界。

- 两个控制场次结束后逐项校验 18 项配置/字典/options 等恢复清单，全部一致；原客户端缓存已归位，25565 端口已释放。

采样复用项目已有 `EgressPipeline` 成功写出计数与原始包导出。新增 `TrafficProfileProbe`、`input` 场景步骤及包装/分析脚本均用于开发冒烟，未改动实体复制、区块交付、压缩或 AFK 产品策略。前置 XERJ 查询未取得相关社区实现，本轮以仓库现有计量路径为依据，没有复制外部源码。

采集启用了同步 JSONL 导出，有额外 CPU/I/O 开销；本轮稳定 20 TPS 不等同于无采集的性能上限。计数中的压缩 CPU 仅覆盖 codec，Windows 短作业 CPU 时钟有量化误差。短窗口不能代替数小时挂机的积压、恢复和误判测试。
