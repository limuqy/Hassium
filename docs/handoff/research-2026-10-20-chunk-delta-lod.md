## 4. 渐进式数据表示：候选设计

### 4.1 空间层级与真实数据

候选结构是固定空间节点下的分层体素：粗层保留可渲染摘要，细化数据保留恢复精确方块的依据。低精度 LOD 是有损显示，最终真实区块的方块状态与生物群系必须精确还原。

必须区分“代表材质是石头”和“内部所有方块都是同一状态”。只有权威数据确认完全均匀时，客户端才可以不下载子层而精确展开；隐藏洞穴、矿石、流体及方块属性不能从外观猜测。

候选编码按节点或小块择优：

| 模式 | 含义 |
|---|---|
| 均匀 | 一个精确状态及覆盖范围，子层可以直接展开 |
| 继承/补差 | 以双方确定的父级预测为基线，发送差异掩码和替换状态 |
| 细分 | 发送八个子区域的结构及必要内容，后续可继续细化 |
| 独立子块 | 差异密集时使用局部调色板和压缩，不强制补丁 |

方块状态是离散类别，补差优先采用替换位置与状态、共享调色板等方式，不假设数值相近的 registry ID 具有空间或视觉意义。渲染代表材质与压缩预测代表值可以不同，但必须计入额外元数据成本。

### 4.2 精度升级与缓存

候选数据流：

```text
粗 LOD → 细化补丁 → 细 LOD → 精确方块/群系
                                  ↓
                  补齐必要附属数据、权威校验、现有算光
                                  ↓
                           真实区块交付
```

- 允许跨级细化：传送/高速移动时不能强制逐层请求并等待往返。
- 有旧完整区块、SeedGen 结果或其他已确认基线时，与 LOD 基线的补丁比较；优先使用总成本更低的路径。
- 降低显示精度不立即删除已下载细节；以预算、热度和迟滞管理缓存，支持掉头/往返复用。
- 每次选择比较包含头、调色板、映射、索引与压缩的完整字节；“粗层＋全部补丁”不保证比一次 FULL 更小。
- 缺失/淘汰基线时改用可独立解码的子块或 FULL；不能让接收方依赖尚未发送或已经删除的数据。

### 4.3 基线一致性与属性分层

- 每个补丁明确世界/维度、空间节点、精度、映射版本、基线标识和目标版本/哈希；字段形式待研讨。
- 同一个粗摘要可能对应多种细节。粗层外观未变不代表精细区块未变，需要独立的细节版本或内容标识。
- 哈希只是校验/索引，不能反推出旧内容。服务端是否保存旧快照、确定性重建基线或拒绝该补丁路径，需明确内存与保留期限。
- 同一批父子细化数据来自一致快照；世界变更期间不得混合不同版本层级。更新合并与父级失效传播需有界。
- 方块状态、生物群系、方块实体客户端更新数据、高度图和光照分别说明来源；地形 hash 不能代替方块实体校验。
- 可视 LOD 光照可以近似；真实区块仍须走现有正确光照路径。不得把未完成细化的区域标成完整缓存命中或可交互区块。

## 5. 视距、持续飞行与调度

候选分区为近景真实区块、过渡/预取带、按距离分层的远景 LOD；具体半径未定。服务器模拟距离、实体跟踪距离与地形显示距离分别讨论，不能随意捆绑。

持续直线飞行时，大量侧翼只需 LOD，不会进入真实区块范围。这是主要收益来源；进入近景的地域再通过补差减少重复传输。对于长直线、静态地形、无缓存、固定高度范围的两档简化模型：

```text
R = LOD 视距，r = 真实区块视距
C = 同面积粗 LOD 字节，D = 升级补丁字节，F = 完整数据字节
持续移动的地形流量比 ≈ (R × C + r × D) / (R × F)
```

这是条带流入模型，不是首次静态加载的面积模型。转弯、回头、传送、各层级切换、缓存、预取取消和真实高度差必须实测；不能把体素数量的 1/8 缩减直接当成网络字节缩减。

调度需包含：

- 近景/交互与移动前沿优先、侧翼按需细化，预算按最终字节而不只按柱数。
- 速度/方向可影响预取优先级，但不取消玩家回头后应有的交付。
- 测量粗层已经发出后又升级、过期取消和重复请求的累计成本。
- 明确当前 `serverVD ∪ OVD` 与拟议真实区块范围的迁移契约；不能只在现有交付门外加一个半径过滤器。
- 服务端 LOD 优先从已生成地形/一致快照构建，缓存供多人复用；远处尚未生成的地形仍可能需要昂贵的 worldgen，单独列成本。

## 6. 必须保留的正确性边界

- `LightNeighborhoodGate` 的真实 3×3 邻域与光照完成门继续成立；LOD 不能冒充算光邻柱。
- 光环按真实形状的切比雪夫膨胀计算，不能用简单扩大 VD 替代；光环不进真实客户端交付域。修改范围前读 [光环交接](handoff-2026-09-19-light-halo-selfdriven-delivery.md) §3.3 的实现修正与交付域约束。
- 影子端 POI / SectionStorage / 注册表访问遵循 `ShadowPoiGate` 与影子主循环串行化，不以新增锁替代。
- 1.20.1 注册表窗口与 Forge 旧载体，1.21.1 NeoForge Payload/codec 分别核对；不能从 26.x 直接照搬签名或加载器。
- 远景只承担显示，不提供碰撞与方块实体交互；真实区块完成并校验前不暴露成完整游戏状态。
- 沿用唯一 vanilla TCP。新消息需能力协商和明确的无能力回退，具体协议版本待研讨；不恢复已退役 UDP/网关。
- OVD、缓存和 SeedGen 已实现的零下载路径单独计量，避免用新增 LOD 流量换来虚假的“相对原版”收益。

## 7. 实验与阶段门

### 7.1 数据与体积实验

两个重点组合分别准备可加载的存档，覆盖平原、森林、山地/洞穴、海洋、城市/建筑、方块实体密集区域及下界。保留坐标、版本、Mod/注册表清单和快照标识。

同一地域比较：

1. 当前 Hassium FULL（实际剥光与压缩配置）和当前 DELTA。
2. 改进的精确差异、附属数据增量与跨柱复用候选。
3. 各精度独立 LOD。
4. 粗 LOD 后重新发 FULL。
5. 粗 LOD 加逐级/跨级细化补丁，直至精确重建。

分别报告原始样本数、序列化字节、压缩字节、带协议封装的传输字节、磁盘缓存、堆/原生内存、GPU 资源（接入后）及生成/解码 CPU。完整金字塔缓存的占用和单层按需缓存分开，禁止混用口径。

编解码阶段要求最终方块/属性精确一致，覆盖均匀区域、稀疏修改、复杂混合状态、注册表映射变化、缺基线、旧版本及损坏补丁；未知或错误数据不得发布成真实区块。

### 7.2 路线与更新实验

| 场景 | 重点 |
|---|---|
| 冷启动、传送、首次大视距 | 首屏、完整就绪时间、无基线退路 |
| 持续直线飞行 | 前方升级与两侧长期 LOD 的独立计量、累计净字节 |
| 转弯、掉头、重复往返、距离边界徘徊 | 细节缓存复用、迟滞、重复细化和取消开销 |
| 缓存命中、SeedGen 开/关、OVD | 与当前真实基线比较，识别原本零下载的区域 |
| 放置/挖掘、爆炸、流体、光源和方块实体变化 | 版本传播、细节与粗外观不同步、补丁一致性 |
| 多玩家共用地形 | 服务端生成/压缩缓存复用、每玩家实际网络成本 |
| 屋檐/洞口移动、跨维度、重连 | 原有光照红线、交付缝隙和世界隔离 |

每个候选先独立 A/B，再组合。历史 master / 26.x 结果不替代两个重点组合的原生验证。新增 LOD 场景及采集工具尚未实现，不能直接假设现有冒烟脚本已支持。
