**关键发现：**
1. **1.20.1 是唯一 ROUND2 ZSTD 优于 Zlib 的版本** — 因为 ROUND2 仍有实质区块加载（过期区块重新推送），ZSTD 在大负载上发挥优势。
2. **1.20.2+ ROUND2 ZSTD > Zlib**：ROUND2 的网络流量很小（100-200 KB），主要是 OVD 缺失区块的补量、心跳、少量更新包。ZSTD 每帧的 framing 开销（4+ bytes frame header + 4 bytes checksum）在这些小包上占据显著比例，导致实际线缆字节超过 Zlib 估算。
   - 这是 ZSTD 的**已知特性**而非 bug：ZSTD 对小数据块（< 256 bytes）的压缩效果不如 Zlib，且有固定开销。在 ROUND2 这种极小流量的场景下，带宽从 ~150 KB 涨到 ~200 KB 实际上是绝对数值很小的劣化（~50-100 KB）。
3. **1.21.2 估算器输出 0 B** — 小 bug，Zlib 估算器未收到数据帧时返回 0，导致 0.0% 百分比无意义。

### 需要关注的异常

1. **NeoForge 1.20.2-1.20.4 光照缓存命中率低（70-72%）** —— 可能是区块卸载时序差异导致缓存写回不及时。fabric 同版本 ~87-98%。建议检查 `CacheSaveQueue` 或 `ClientCacheLoadQueue` 在 Forge 平台下是否在区块卸载前完成写盘。
2. **1.21.2 Zlib 估算器输出 0** —— `estimate(int)` 返回 0 导致统计显示 `0.0%` 和 `0.00:1`。建议修复估算器在小负载下的兜底默认值。
3. **ROUND2 ZSTD > Zlib** —— 纯统计现象，ROUND2 流量极小（100-200 KB），ZSTD framing 开销在绝对数值上微不足道。无实际性能影响。
